# AWS Backend TDD

## 基準

- テスト数ではなく、現実の不具合を検出できることを重視する。
- 既存コード・契約・テスト・呼び出し元を確認し、変更範囲を限定する。
- 同じ失敗への修正・再検証は最大2回。解決しなければ事実を報告して止める。
- 利用者とプロジェクトの指示を優先し、権限・依存・作業範囲を勝手に増やさない。

## テストを選ぶ

振る舞い・外部契約・権限・データ保持が変わるかを判断する。
説明文・翻訳・整形だけなら形式的なテストを追加しない。

先に「どんな誤実装で、このテストが失敗するか」を説明する。
観測境界と変更のリスクを短く示し、重要な仕様が曖昧な場合だけ確認する。

期待値は仕様・手計算・独立したデータから決める。
公開境界の結果を検証し、内部構造やモックの存在だけを固定しない。
要求引数・回数・順序が契約なら、それも検証する。

## 安い階層から進める

| 階層 | 自動実行の条件 |
| --- | --- |
| unit | 実AWSへ接続しない |
| local-integration | 接続先・認証・外向き通信・起動完了を確認済み |
| real-aws | 対象・操作・費用・後片付けが許可された範囲 |

unitで証明できない部分だけを上の階層へ進める。
同じ契約を証明できるなら、費用と副作用が最小の検証を選ぶ。

既存のディレクトリ・マーカー・実行コマンドで階層を分離する。
未分類の全体テストは内容を調べるまで自動実行しない。
ローカルという名前やエミュレーターの成功を、実AWSの安全・互換性と同一視しない。

## 小さくRED → GREEN → REFACTOR

1. **RED**：1つの振る舞いのテストを実行し、意図した動作不足による失敗を確認する。
   構文・依存・起動待ち・通信障害はREDの証拠にしない。
2. **GREEN**：必要な実装だけで通す。期待値を弱めたり、将来用の機能を追加しない。
3. **REFACTOR**：必要な整理だけ行い再実行する。不要なら省略する。

既に通るテストを無理に壊さない。
テスト前のコードを自動削除せず、事後テストをREDとして報告しない。
対象テストから関連チェックへ広げ、既存の失敗と今回の失敗を区別する。

## 必要な参考だけ読む

本文で観測境界と階層を決め、該当する参考だけ読む。
分類が曖昧なら境界の確認に戻り、念のための全読み込みはしない。

参照パスは、読み込んだSKILL.mdの親ディレクトリを基準に解決する。
作業ディレクトリを基準にせず、必要なファイルを明示的に開く。
所在不明・読み取り不能なら推測で補わず、未確認として報告する。

- SDK・Lambda・非同期・永続化・ローカル統合・実践例：
  [testing.md](references/testing.md)
- IAM・IaC：
  [iam-iac.md](references/iam-iac.md)
- 実AWSへ接続する前：
  [real-aws.md](references/real-aws.md)

## 安全と報告

秘密情報・個人情報をログ、fixture、検証記録へ残さない。
テストを通すためにIAMやネットワークを広げない。
不確かなAWS仕様は公式資料で確認する。

完了時は、状態、変更ファイル、階層別コマンドと結果、
RED/GREEN記録、未検証事項・リスク・次の行動を簡潔に示す。
real-awsを実施した場合は、後片付けの結果・確認方法・残存物も必ず報告する。
設定保存、ローカル成功、デプロイ成功、実環境成功を混同しない。
