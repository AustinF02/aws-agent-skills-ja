# IAM・IaCの検証

今回影響する対象だけ確認する。AWS側APIを使う前にreal-awsの条件を確認する。

## IAM

まず生成ポリシーのAction・Resource・Conditionをローカルで確認する。

許可だけでなく、最小権限を守る否定ケースを選ぶ。
例：対象リソースでは許可され、対象外では拒否されること。

AWS側ではAccess Analyzerのポリシー検証や、
IAM Policy Simulator／simulate-principal-policyを使い分ける。
評価するaction・resource・contextを明示する。
ポリシー文法の検証を実効権限の証明にせず、シミュレーターの制限も確認する。
実権限を確かめるためだけに、危険な書き込みを実行しない。

## IaC

- CloudFormationは原則YAML。cfn-lint、必要ならcfn-guardを使う。
- CDKの生成テンプレートは、重要なリソース・プロパティ・ポリシーを検証する。
  全体スナップショットだけに依存しない。
- synthでもlookupや外部処理があり得るため、実行内容と接続先を確認する。
- 適用前にcdk diffやCloudFormation変更セットで、置換・削除・IAM差分を確認する。
  使用バージョンと実行方式を調べ、クラウド操作としての許可を確認する。
- 変更セットの作成と実行は別の操作。差分表示を副作用なしと決めつけない。
- 必要な場合だけドリフトを確認する。変更差分とドリフトを混同しない。

ローカル検証、AWS側検証、適用後の動作を区別して報告する。
