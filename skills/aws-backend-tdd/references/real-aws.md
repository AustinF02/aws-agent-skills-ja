# 実AWS検証の境界

実行前に、対象アカウント・リージョン・リソース、読み取り／書き込み、
費用・試行上限・停止条件、作成物・保持物・後片付けを確認する。
既存の認証方式を勝手に変更しない。

- 既存の承認範囲で実行し、不足する重要な許可だけ確認する。
- 同じ契約を証明できるなら、負荷試験より単発実行、全面デプロイより限定的な検証を選ぶ。
  validateやdry-runで証明できる範囲を超えて、成功を主張しない。
- 可能なら共有環境から分離し、検証用リソースを識別可能にする。
- 実サービスを待つ場合は、期限・回数・間隔・終了条件を定める。
- デプロイ、IAM変更、データ更新・削除を、単なるテストとして無断実行しない。
- 同じ失敗への修正・再検証は本文の最大2回を守る。

## 終了時

失敗・中断時も、許可された後片付けを試みる。
今回作成した対象だけを扱い、既存データや共有資源を巻き込まない。

削除要求の成功だけで完了とせず、対象の消失と残存物を確認する。
未承認・実行不能・削除失敗なら停止し、残る費用や必要な操作を報告する。

完了報告には、後片付けの結果、確認方法、意図的な保持物、
削除できなかったものを記載する。残存なしも確認した場合だけ述べる。
