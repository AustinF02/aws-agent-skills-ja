# AWS Events認証

AWS EventsにはAWS Builder IDのOAuthを使う。aws login、IAMキー、EventBridgeとは別の認証。
公開イベント一覧は認証不要の場合があるが、登録制イベントのカタログと個人予定には認証が必要。

## 現状を確認して保持

OS、エージェントとバージョン、既存awsevents設定、対象イベントを確認する。
動作中の認証と無関係な設定を保持し、他人の認証情報をコピーしない。
利用クライアントが対応するOAuthを優先する。標準設定やmacOS用の代替手順は [setup.md](references/setup.md) を読む。

## 認証して読み取る

- 初回のブラウザーログインや接続設定の変更は、承認範囲を確認して実施する。
- 承認済みの作業内では既存セッションを必要時に更新し、読み取りのたびに再確認しない。更新できず新たな対話ログインが必要な場合は別の手順として扱う。
- 同梱の [events_auth.py](scripts/events_auth.py) はmacOS専用の代替手段。トークンをKeychainに保存し、読み取り専用getコマンドが内部でBearerヘッダーを付ける。
- curl用にトークンを取り出さずヘルパーを使う。401なら一度だけ更新・再試行する。403は登録・認可を調べ、ログインを繰り返さない。
- 新しいrefresh tokenを保持し、応答のexpires_inを使う。更新してもBuilder IDセッションを無期限には延長できない。
- 別途依頼されない限り、予約・取消・お気に入り・個人予定を変更しない。同梱RESTヘルパーが公開する操作はGETのみ。
- パスはこのSKILL.mdの親ディレクトリから解決し、必要な参考だけ読む。

## 秘密情報と検証

パスワード、トークン、認証ヘッダー、コールバックURL・コード、Keychain内容を出力しない。
headersはMCPクライアント内部のヘッダー取得にだけ使い、表示される端末で実行しない。
公開OAuthクライアントIDは全利用者共通の識別子で、秘密情報ではない。
個人予定やローカル設定をIssue・テスト・ログへ掲載しない。

設定保存、認証成功、依頼された読み取りを区別して確認する。
MCPはツール一覧を取得してから接続成功と報告する。
OS・保存方式の制約、実施した検証、未確認のアプリ動作を明示する。
本スキルは行動の指針であり、権限の強制や安全性を保証する仕組みではない。
