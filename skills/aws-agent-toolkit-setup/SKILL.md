# Agent Toolkit for AWSの導入

作業開始時に [AWS公式setup.md](https://raw.githubusercontent.com/aws/agent-toolkit-for-aws/refs/heads/main/setup-instructions/setup.md) を取得して全文を読む。古いコマンドを記憶で実行しない。このスキルは公式本文のコピーではなく、日本語案内と既存環境を守るための補助である。

## 入力と境界

OSを検出し、利用エージェント、AWSプロファイル名、利用リージョン、新しいAWS体験か従来の体験かを確認する。既に提示された情報を再質問しない。秘密情報は受け取らず、認証は利用者のブラウザー内で行う。SSOや静的キーを使う既存プロファイルを勝手に別方式へ変えない。

既存のCLI、uv、MCPエントリー、ルールファイル、同名スキルを確認する。AWSリソース作成・デプロイ・IAM変更は対象外。導入の許可とログインの許可を明確にする。

## 公式手順の適用

- CLIが存在しても `aws configure agent-toolkit help` を確認する。未対応なら公式の更新手順を使い、既存インストールを削除しない。
- 指定リージョンが設定済みなら再設定しない。STSで既存認証が有効なら再ログインを省略し、その差分を説明する。
- 複数エージェントが検出された環境で `--yes` により全部を書き換えない。対話ウィザードで利用者が選んだエージェントだけを選択する。
- 現行公式手順に従いToolkitサービスのリージョンを指定する。ワークロードのデフォルトリージョンを、そのためだけに変更しない。
- 生成されたMCPの起動コマンド・引数を保持し、必要な名前付きプロファイルのenvをクライアントの正式な形式で追加する。
- 既存の同名MCPやスキルは上書きせず、差分を提示して統合方法を確認する。
- AWS体験別ルールは公式の該当ファイルを取得する。AGENTS.md、CLAUDE.md、Kiro steeringの既存本文を保持し、境界マーカー付きで一度だけ追加する。プロジェクト独自ルールを優先する。
- 公式手順と現行の認証ドキュメントで有効期限の説明が異なる場合、固定の90日更新などを保証せず、不一致と確認できた範囲を説明する。

## 完了条件

指定プロファイルでスキルカタログを取得し、インストール先とスキルファイルを確認する。MCPはtools/listまで検証する。新しいセッションでの実動作は未確認ならそのまま記載する。成功したことと、利用者の操作待ち・未検証の項目を日本語で分ける。

失敗時は [公式トラブルシューティング](https://raw.githubusercontent.com/aws/agent-toolkit-for-aws/refs/heads/main/setup-instructions/setup-troubleshooting.md) の該当箇所を読む。無制限に再試行しない。最終例にあるゲームの作成・デプロイは別依頼であり、このセットアップに含めない。
